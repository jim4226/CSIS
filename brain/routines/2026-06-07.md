### opened-PR — Advisor tool max_tokens parameter (platform release notes, June 2)

- Source: platform.claude.com/docs, published June 2, 2026 (max_tokens cap); tool launched April 9
- Theme: 1 (Multi-agent coordination) + 2 (Trust + verification)
- Touches: `csis/backends/base.py`, `csis/agents/base.py`, `csis/backends/anthropic.py`, `csis/config.py`, `csis/agents/coordinator.py`
- Size: small (≤200 LOC + 13 regression tests)
- Risk: low — no chokepoints touched; advisor_model=None is the default, preserving existing behavior
- PR: #39

The advisor tool pairs a fast executor model with a high-intelligence advisor that provides strategic guidance mid-generation inside a single API request. For CSIS this maps to the Builder role: generate most tokens at Sonnet rates while an Opus advisor shapes the plan before it crystallises. The June 2 `max_tokens` cap makes cost predictable within the BudgetTracker's iteration budget, which is the immediate trigger for this PR. The single chokepoint is `AgentContext.complete()` — the one place every sub-agent LLM call is constructed — and adding `advisor_model` there propagates via the existing protocol without touching the Coordinator loop or memory primitives.

### opened-PR — Security guidance plugin tiered-review → fast_audit_check
- URL: https://code.claude.com/docs/en/whats-new/2026-w22.md
- Plugin docs: https://code.claude.com/docs/en/security-guidance.md
- Source: code.claude.com/docs (Week 22, May 25–29, 2026)
- Theme: 7 (Curiosity / frontier-item generation — automated red-teaming) + 2 (Trust + verification)
- Touches: `csis/agents/auditor.py`, `csis/agents/coordinator.py`
- Size: trivial (≤80 LOC + 7 regression tests)
- Risk: low — pure-Python pre-check; does not touch TierMismatch cleanup path or promotion CAS
- PR: #40

The security-guidance plugin runs: fast pattern check per edit → model review per turn → deeper agentic review on commit. The CSIS equivalent is `fast_audit_check()` (fast, no LLM) → `write_why_doc()` (existing model review) → future P1.3/P1.4 V3/V4 (deeper review). The pre-check catches obvious violations (failed cert slipping to auditor step, empty candidate_entries returning as a silent zero-delta promotion) before spending tokens on the LLM pass. Tier mismatches intentionally remain with `_build_diff()` (cycle-6 E1 fix) to preserve the existing TierMismatch rollback machinery. The single insertion point is the coordinator's auditor block, before `write_why_doc()`.

### deferred — Claude Managed Agents self-hosted sandboxes on AWS (May 29)
- URL: https://platform.claude.com/docs/en/release-notes/overview (May 29 entry)

- Source: platform.claude.com/docs, published May 29, 2026

- Touches: would touch `csis/substrate/` (new SandboxedRunner or SandboxMode enum), `csis/config.py`, potentially `csis/agents/builder.py`
- Size: medium (≤500 LOC including interface, config plumbing, and tests)

- Design sketch: Add `SandboxMode` enum (`LOCAL | MANAGED_AGENT | SELF_HOSTED`) to `csis/substrate/capability.py`. Add `sandbox_mode: SandboxMode = SandboxMode.LOCAL` to `CSISConfig`. The self-hosted sandbox pattern (running tool execution in your own infrastructure vs Anthropic's) maps directly to the distinction CSIS needs between dev (local) and production (isolated) Builder execution.
- Why deferred: Medium scope requiring a new substrate module + protocol + config wiring. The ROADMAP already tracks this as P1.2, and P1.1 (real Dreams API) and P1.2 are the declared next milestones. Wants dedicated design discussion rather than a routine-run PR.
