### deferred — Mid-conversation tool changes (beta)
- URL: https://platform.claude.com/docs/en/release-notes/overview (July 24, 2026 entry)
- Source: platform.claude.com/docs/en, published 2026-07-24
- Theme: 6 (Substrate / capability boundaries — tool use) and 4 (Persistent memory + context — prompt caching)
- Touches: `csis/substrate/capability.py` (`CapabilityTag`, `PHASE_0_CEILING`), `csis/safety/tier_guard.py`
- Size: medium
- Risk: medium (adjacent to, though not one of, the cycle-9 chokepoints — it would change what a `CapabilityTag`'s `tool` field can mean mid-session)
- Design sketch: The new Messages API beta (header `mid-conversation-tool-changes-2026-07-01`, on Fable 5 / Mythos 5 / Opus 4.8 / Opus 5) lets a caller add or remove tools between turns of the same conversation without invalidating the prompt cache. CSIS's `AnthropicBackend` (`csis/backends/anthropic.py`) currently does plain text completion — no `tools=` plumbing exists anywhere in `csis/` today (grep confirmed zero hits). Before this is adoptable, CSIS would need actual tool-calling support in the backend, plus a mapping from `CapabilityTag.tier` to the toolset exposed at each turn, so a tier promotion/demotion (e.g. Builder T1 gaining a sandboxed-exec tool after Auditor sign-off) could add a tool mid-session instead of requiring a fresh conversation. That mapping is the load-bearing part: it would sit next to `TierGuard.ceiling()` and the `PHASE_0_CEILING` check in `csis/substrate/capability.py`, since a wrong mid-session tool grant would bypass call-site enforcement without a new escalation record in the event log.
- Why deferred: no tool-calling exists in CSIS at all yet, so this is a two-step change (add tool-use support, then wire it to capability tiers) — squarely medium-or-larger, and it sits next to (not on) a cycle-9 chokepoint, which the file's risk rubric treats as medium risk. Worth a real design discussion before code, not a same-day PR.
