## Observation: ledger/PR-history mismatch (read this before trusting `index.md`)

Before scanning sources, I checked GitHub for existing `claude/daily-*` branches to dedup against (per the "don't reopen a PR for a URL you already opened a PR for" rule). That search turned up **90 open pull requests** from this routine, one "routine log" PR per day going back to 2026-05-23 (PR #8) through yesterday (#102), plus ~35 code PRs with slugs like `agent-role-tier-enforcement`, `tripwire-severity-score`, `memory-domain-guard`, `adversarial-critic-vote`, etc. **None of these 90 PRs have been merged** — they're all still sitting open as drafts.

This matters because `brain/routines/index.md` on `main` still reads its original placeholder (`"Ledger initialized; first real entries land on the routine's first scheduled run"`) — meaning every prior run's log and index updates live only on their own unmerged branches, never on `main`. So the "read state" step this file prescribes (`cat brain/routines/index.md`, read the 14 newest `brain/routines/*.md` files) is, in practice, reading an empty ledger every single day, regardless of how many runs have actually happened. Two consequences worth flagging to a human:

1. **Dedup is currently branch-name-based, not ledger-based.** I worked around this today by pulling the PR list directly (title/slug/date) instead of trusting `index.md`, since that's the only place the real history lives. That's a reasonable stopgap but it's not what this file specifies, and it gets more expensive to do by hand as the PR count grows.
2. **This is very likely not the intended operating mode.** A routine whose only artifact is draft PRs that pile up unreviewed for 8+ weeks isn't compounding — each day's context (what's already been tried, what's already deferred) is being rebuilt from a GitHub search instead of the durable `brain/` memory the whole `CSIS` project is themed around. Two ways to close the loop: (a) merge the backlog (or the log PRs at least, since those are pure appends and low-risk) so `index.md` starts reflecting reality, or (b) if the intent really is "never auto-merge, human reviews everything," consider whether `index.md`/day-files should be written to `main` directly on a lower-risk path (e.g., the log-only PR, which never touches source code) so state accumulates even while code PRs wait for review.

No action taken on the 90 open PRs themselves — closing or merging them isn't this routine's call to make unilaterally.
