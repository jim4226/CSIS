- Touches: `csis/contracts.py` (`MemoryEntry`), `csis/memory/store.py` (`promote()`), `tests/test_memory.py`
- Size: small (≤200 LOC)
- Risk: medium — adding a domain guard in `promote()` touches the promotion path, which is adjacent to the cycle-9 `writer_iteration_id` and promotion-CAS chokepoints
- Design sketch: Add `memory_domain: str | None = None` to `MemoryEntry` in `contracts.py`. Add a matching `domain: str | None = None` constructor parameter to `MemoryStore`. In `promote()`, if both `store.domain` and `entry.memory_domain` are non-None and they differ, raise `TrustViolation("cross-domain promotion rejected")`. Write a regression test that creates two stores (domain="lean_math" and domain="pr_maintenance"), writes a candidate to the lean_math store, then asserts promotion into the pr_maintenance store raises `TrustViolation`. The `None` default preserves full backward compatibility — all existing callers pass no domain and continue to behave identically. This directly implements the Claude Tag "separate Claude identities with scoped memories" guarantee at the CSIS memory layer, closing a gap the current architecture doesn't enforce.
- Why deferred: Medium risk (promotion path touch); needs a regression test that fails before the change and passes after per CYCLES.md cycle-6 E1 cautionary tale. Also need to verify whether domain adapters (`lean_math`, `pr_maintenance`, `self_improve`) currently share a single `MemoryHierarchy` instance (if they already hold separate hierarchies, the isolation is already structural and the MemoryEntry-level guard may be redundant).
