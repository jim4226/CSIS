- Source: anthropic.com/news, published 2026-05-28
- Theme: 1 — Multi-agent coordination
- Touches: `csis/agents/coordinator.py` (`run_continuous`, `run_iteration`)
- Size: medium (≤500 LOC)
- Risk: high — touches `Coordinator.__init__`, iteration-level concurrency invariants
- Design sketch: Opus 4.8's "Dynamic Workflows" enables orchestrating hundreds of parallel subagents. `run_continuous()` already documents the placeholder: "For the prototype this is a synchronous loop. The Anthropic scheduler (≤25 concurrent threads) would replace this in a real deployment." A real implementation would split frontier items across a `ThreadPoolExecutor(max_workers=config.max_threads)`, with each worker calling `run_iteration()` on its own `MemoryHierarchy` (the cycle-9 H6 comment explains why shared hierarchy + concurrent iteration is unsafe in Phase 0). The PR would also need to add a `tests/test_parallel_coordinator.py` that demonstrates two independent coordinators racing to promote and verifies no cross-contamination.
- Why deferred: High risk — concurrent `run_iteration` touches the cycle-9 chokepoints (`Coordinator.__init__` shape, `writer_iteration_id` tagging, promotion CAS). Needs a cycle-10-style red-team pass before merging.

### deferred — Opus 4.8: mid-conversation system blocks (`mid_conv_system`)
- URL: https://www.anthropic.com/news/claude-opus-4-8
- Source: anthropic.com/news, published 2026-05-28
- Theme: 4 — Persistent memory + context
- Touches: `csis/backends/base.py` (`LLMRequest`), `csis/backends/anthropic.py` (`complete`), `csis/agents/base.py` (`AgentContext.complete`)
- Size: small-to-medium (≤300 LOC including tests)
- Risk: medium — changes the `LLMRequest` interface contract that every agent uses
- Design sketch: The Messages API now supports `MidConversationSystemBlockParam` (`type: "mid_conv_system"`) — system instructions embedded in the message array without breaking prompt caching. CSIS currently sends single-turn requests only. To leverage this, `LLMRequest` would gain an optional `conversation_history: list[dict]` field; `AnthropicBackend.complete()` would build a multi-turn `messages` list, inserting `mid_conv_system` blocks at role-transition boundaries (e.g., when the Verifier re-reads a plan the Builder produced). `AgentContext.complete()` would accept and thread the history through. All existing single-turn callers stay unchanged (history defaults to `[]`).
- Why deferred: Medium risk — changing `LLMRequest` propagates to every agent. CSIS is currently single-turn per call; adding conversation history is a pre-condition for this feature to add value, which makes the true size larger than the LOC count suggests. Worth picking up after a multi-turn story is scoped.
