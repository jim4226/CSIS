### deferred — GRAM: Gradient-Routed Auxiliary Modules (dual-use knowledge compartmentalization)
- URL: https://www.anthropic.com/research/off-switch-dual-use
- Source: Anthropic Research, published 2026-07-08
- Theme: 3 (constitutional/safety primitives, capability tiers) and 6 (substrate/capability boundaries)
- Touches: conceptually `csis/safety/tier_guard.py`, `CSIS-architecture.html` §9 (capability tiers)
- Size: large (research parallel, not a direct port)
- Risk: n/a (no code change proposed)
- Design sketch: GRAM adds removable per-layer modules at *training* time so dangerous knowledge can be deleted from a model's weights rather than merely gated at the call site. CSIS's own capability-tier substrate (T0/T1 ceiling, `tier_guard.py`) operates entirely at the orchestration layer — it tags and checks primitive calls, but has no notion of what the underlying model *knows*. If CSIS ever ships the local-backend adapter invited in ROADMAP.md ("Open invitations to contributors"), a GRAM-style compartmentalized model would be a natural complement: `tier_guard` gates *access*, GRAM would gate *existence*. Not actionable today because Phase-0 doesn't own model weights for any backend (mock or Anthropic API).
- Why deferred: no CSIS chokepoint exists yet to attach a regression test to; this is a Phase-2+ idea contingent on a local-model backend landing first. Worth a short mention in ROADMAP.md's open-invitations section on a future run once someone picks up the local-backend-adapter invitation.
